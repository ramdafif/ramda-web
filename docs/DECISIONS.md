# Decisions

1. This branch starts with an independent Git root. No code or history from `main` is reused. Target: `ramdafif/web-pribadi`, branch `web-pribadi/NEW`.
2. The two supplied images are brand references, not desktop/mobile website mockups. The layout follows the written dark/bronze design system. The original raster monogram is used without inventing a replacement vector or personal photo.
3. All CMS entities share a portable SQLAlchemy `content_item` storage table. The `kind` discriminator selects a strict Pydantic schema for each entity, including localized fields. Operational entities (users, leads, media, audit, rate counters, AI sessions/usage/budget) use dedicated tables. The admin exposes each content entity independently.
4. Working data and public snapshots are distinct. Publish atomically updates public snapshots, then requests secret-protected Astro revalidation. Astro's fallback TTL is two seconds; Nginx HTML microcache is at most one second. No cached Flask public API in Nginx. This keeps the normal publication window below five seconds even when the callback fails.
5. All initial content lives in `backend/seed/content.json`. Every seed record is a placeholder. Unverified stats and placeholder testimonials are always suppressed, not merely labelled. No invented clients, usage, achievements, social links, portrait, or prices. Project statuses follow the supplied seed and must be reviewed by the owner. Only approved content should be marked verified.
6. No website mockup with article titles was supplied. Four descriptive editorial placeholders are seeded as unpublished drafts; they are not presented as titles extracted from a mockup.
7. Latest packages are resolved from the registries at implementation time and pinned exactly. TypeScript 7 is not yet supported by `@astrojs/check`; the latest compatible stable TypeScript 6 is used. Python 3.12 and Node 24 LTS are the deployment baseline.
8. Sites hosting runs Cloudflare Workers and cannot host this required Flask + Node + MySQL stack. The deliverable is the requested repository branch and Ubuntu deployment configuration. No alternate stack or unrequested hosting project is created.
9. Public JSON write endpoints require exact same-origin JSON, rate limits and Turnstile rather than session CSRF tokens. Every admin mutation, including login, logout, upload, reorder, publish and import, uses Flask-WTF CSRF.
10. The demo defaults to disabled and fails closed without a configured, allowlisted model and API key. Retrieval uses BM25 over published snapshots only. Conversation text is never persisted. Usage stores conservative UTF-8 input bounds and maximum output reservations; the dashboard reports an upper-bound estimated cost rather than claiming provider billing precision. Failed/interrupted requests retain their reservation.
11. Public contact submissions are committed before notifications. Notification failure does not discard the lead; its delivery state remains visible in the inbox. Notifications are disabled in seed content and only target destinations explicitly configured by the owner.
12. Integration testing uses local SQLite and mocked provider/notification transports. Real provider streaming, live Turnstile and outbound notification delivery require owner credentials and must be verified on the deployed domain. They are never claimed as live-tested without those credentials.
13. Backup import validates an entire content JSON before committing working data. Upload ZIP restore validates filenames, expanded sizes and image bytes, strips metadata and sanitizes SVG. Admin accounts, secrets and lead personal data are excluded from the portable content backup; full server backups cover the database separately.
14. Astro ignores underscore-prefixed files in the pages directory. The internal `/__revalidate` route is registered through an Astro integration from `src/endpoints/revalidate.ts`. HTTP smoke tests cover the compiled endpoint, its authorization and actual draft→publish→SSR updates.
15. Placeholder verification is versioned alongside public data (`public_is_placeholder`). Marking a record verified in a working draft cannot accidentally expose a previously hidden statistic/testimonial before Publish.
16. The current LHCI CLI pulled known vulnerable development-only dependencies. It was replaced with the latest Lighthouse + chrome-launcher APIs and a small CI runner enforcing the same mobile category/LCP/CLS gates. Full npm audit, including development packages, is required and passes after the replacement. No vulnerability suppression or forced package downgrade is used.
17. A schema upgrade on existing seeded SQLite data is tested explicitly, including the safe server default for the new public verification snapshot column. Fresh setup does not rely on `db.create_all` in production.
18. Git CLI has no credential in this environment. The account's repository metadata reports push permission, but GitHub's Git write API returns `403 Resource not accessible by integration`. The complete local branch/history is preserved for delivery; neither main nor a remote NEW branch is modified. Reconnecting an integration with repository contents write permission is needed for a native push from this session.
19. Current official GitHub Actions releases were checked and pinned to their exact commit SHAs. The latest stable runtime-compatible TypeScript 6 remains the sole package-version compatibility exception. Application dependencies and audit tools otherwise use current registry releases pinned in lockfiles.
